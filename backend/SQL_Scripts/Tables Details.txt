Master Tables
1. PATIENT

Stores demographic information.

CREATE TABLE patient (
    patient_id VARCHAR(50) PRIMARY KEY,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    gender VARCHAR(20),
    age INT,
    date_of_birth DATE,
    phone VARCHAR(20),
    email VARCHAR(100),
    created_at DATETIME,
    updated_at DATETIME
);
2. PATIENT_VITALS
CREATE TABLE patient_vitals (

    vital_id BIGINT AUTO_INCREMENT PRIMARY KEY,

    patient_id VARCHAR(50),

    height_cm DECIMAL(5,2),

    weight_kg DECIMAL(5,2),

    bmi DECIMAL(5,2),

    blood_pressure VARCHAR(20),

    heart_rate INT,

    respiratory_rate INT,

    spo2 DECIMAL(5,2),

    temperature DECIMAL(5,2),

    recorded_at DATETIME,

    FOREIGN KEY(patient_id)
        REFERENCES patient(patient_id)
);
3. PATIENT_DIAGNOSIS
CREATE TABLE patient_diagnosis (

    diagnosis_id BIGINT AUTO_INCREMENT PRIMARY KEY,

    patient_id VARCHAR(50),

    diagnosis_name VARCHAR(200),

    diagnosis_code VARCHAR(30),

    diagnosis_date DATE,

    status VARCHAR(50)
);
4. PATIENT_MEDICATION
CREATE TABLE patient_medication (

    medication_id BIGINT AUTO_INCREMENT PRIMARY KEY,

    patient_id VARCHAR(50),

    medication_name VARCHAR(200),

    dosage VARCHAR(100),

    frequency VARCHAR(100),

    start_date DATE,

    end_date DATE
);
5. PATIENT_ALLERGY
CREATE TABLE patient_allergy (

    allergy_id BIGINT AUTO_INCREMENT PRIMARY KEY,

    patient_id VARCHAR(50),

    allergy_name VARCHAR(200),

    severity VARCHAR(30)
);
6. LAB_RESULT
CREATE TABLE laboratory_result (

    lab_result_id BIGINT AUTO_INCREMENT PRIMARY KEY,

    patient_id VARCHAR(50),

    test_name VARCHAR(200),

    result_value VARCHAR(100),

    normal_range VARCHAR(100),

    result_date DATETIME
);

Enterprise Recommendations

For a real-world Healthcare Digital Twin Platform, I would extend this schema with:

FHIR-aligned tables for Patient, Encounter, Observation, Condition, MedicationRequest, Procedure, AllergyIntolerance, and CarePlan resources to simplify interoperability with EHR systems.
Master reference tables (diagnosis codes, medication catalog, lab test catalog, departments, devices) instead of storing free-text values.
Versioning for digital twins (version_number, effective_from, effective_to) so each simulation and prediction is traceable over time.
User, Role, and Organization tables with RBAC for multi-tenant deployments.
Model registry metadata (model version, prompt version, embedding version) linked to each prediction for reproducibility.
Event and message tables to capture simulation events and asynchronous processing, enabling scalable workflows with queues or event-driven architectures.

This design scales well for FastAPI + LangChain + ChromaDB + MySQL + Agentic AI and supports future expansion into production-grade healthcare systems.
